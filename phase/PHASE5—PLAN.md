# Phase 5：Agent 能力扩展计划

## 目标

将桌宠从聊天助手扩展为能够在用户授权下执行文件、软件、系统和自动化任务的个人 Agent。

## 范围与边界

- 建立统一工具注册、参数校验、调用、结果和审计模型。
- 首期覆盖文件搜索/整理、打开软件、受限命令执行、系统状态读取、定时任务和简单工作流。
- 所有有副作用的工具默认需要用户确认或预授权；不实现绕过系统权限的能力。
- 工具执行与 LLM 决策解耦，LLM 只能提出结构化调用请求。

## 前置条件与依赖

- Phase 2 的会话服务和 Phase 3 的上下文服务可用。
- Phase 0 的 Rust 宿主能够提供受控系统 API。
- 先定义权限等级、允许路径、命令白名单、超时、取消和日志保留策略。

## 实施任务

1. 定义 `ToolManifest`、`ToolRequest`、`ToolResult`、`PermissionPolicy` 和 `AuditEvent`。
2. 实现工具注册表、发现、版本校验、参数 schema 校验和生命周期管理。
3. 实现安全文件工具：搜索、列目录、读取元数据、复制/移动到用户确认的目标。
4. 实现软件启动和系统状态读取，使用平台适配层隔离 Windows API。
5. 实现命令工具的白名单、参数转义、工作目录限制、超时、输出截断和取消。
6. 实现定时任务与工作流：步骤状态、重试策略、失败停止、取消和执行历史。
7. 增加用户确认对话框、预授权管理、拒绝结果和审计日志查看。
8. 将工具结果标准化后回传 LLM，并限制工具调用循环次数和总执行时间。

## 建议接口

- `ToolRegistry.list/get(manifest)`：仅返回已启用且版本兼容的工具。
- `ToolExecutor.execute(request, context)`：执行前完成权限检查，返回结构化结果。
- `PermissionService.check(request, userContext)`：返回允许、需要确认或拒绝及原因。
- `AuditStore.append(event)`：记录工具、调用者、参数摘要、结果状态、耗时和用户决定。

## 安全与执行规则

- 文件路径必须规范化并限制在用户明确授权的根目录内，禁止路径穿越。
- 命令执行默认关闭；白名单只允许固定可执行文件和参数模式，禁止拼接 shell 字符串。
- 删除、覆盖、发送、安装、上传等不可逆或外部副作用操作必须二次确认。
- 工具输出按大小、类型和时间限制，禁止把原始凭据或完整环境变量回传模型。
- 每次调用都带取消信号、超时和审计事件，应用退出时回收子进程。

## 阶段交付物

- 统一工具框架和至少三类本地工具实现。
- 权限确认、预授权、审计和失败恢复机制。
- 定时任务/工作流的最小可用版本。
- LLM 到工具到结果回传的受限执行闭环。

## 验收标准

- 模型无法绕过权限策略直接执行工具；未授权调用会被拒绝并说明原因。
- 合法文件操作、应用启动和系统状态读取可完成，危险操作会暂停等待确认。
- 超时、取消、崩溃和重复请求不会遗留失控进程或重复副作用。
- 审计记录足以回答谁、何时、调用了哪个工具、结果如何以及用户是否确认。
- 工作流在失败时能停止或按明确策略重试，状态可恢复查看。

## 测试与验证

- 权限测试：路径穿越、白名单绕过、危险参数、拒绝和过期授权。
- Executor 测试：超时、取消、输出截断、重复请求和子进程回收。
- 工具契约测试：schema 校验、版本不兼容、缺少参数和错误映射。
- 工作流测试：顺序步骤、失败停止、重试上限、暂停、恢复和取消。
- 安全演练：将恶意指令放入用户文本、网页内容和工具结果，确认不会升级权限。

## 风险与后续入口

- 系统工具的权限边界决定产品安全等级，任何新增工具都必须先补 manifest 和策略。
- Phase 6 MCP 工具必须复用本阶段的权限、审计和取消机制，不得另建绕过层。
- 定时任务会引入后台运行和通知问题，需在 Phase 7 统一接入主动行为调度。
