# Phase 6：MCP 扩展系统计划

## 目标

接入外部 MCP 工具生态，让桌宠能够发现、管理并安全调用 Blender、VSCode、GitHub、Browser 等外部能力。

## 范围与边界

- 实现 MCP Client 的连接、初始化、能力发现、工具调用、断开和重连。
- 支持本地进程和受控远程传输；具体传输实现以 MCP 规范兼容性为准。
- 将 MCP 工具转换为 Phase 5 统一工具模型，并复用权限与审计。
- 不在本阶段开发第三方 MCP Server，也不默认启用任意外部服务器。

## 前置条件与依赖

- Phase 5 的工具 manifest、权限策略、执行器和审计存储已稳定。
- 明确服务器安装来源、版本、启动参数、工作目录、凭据提供方式和网络策略。
- 确定用户可见的服务器信任状态与启停入口。

## 实施任务

1. 定义 `McpServerConfig`、`McpConnection`、`McpCapability` 和生命周期状态。
2. 实现 MCP Client 传输层、初始化握手、协议版本协商和消息关联。
3. 实现工具/资源/提示发现，并把工具 schema 转换为标准 `ToolManifest`。
4. 实现调用代理：参数校验、超时、取消、并发限制、分页和响应大小限制。
5. 实现服务器配置管理、启用/禁用、连接日志、健康检查和重连退避。
6. 将服务器级和工具级权限映射到 Phase 5 `PermissionService`。
7. 在设置页提供服务器列表、信任确认、能力查看、连接状态和错误诊断。
8. 使用 mock MCP server 完成契约与集成测试，再逐一验证目标生态服务器。

## 建议接口

- `McpClient.connect(config)`、`disconnect()`、`listCapabilities()`、`callTool()`。
- `McpAdapter.toToolManifest(capability, server)`：保留来源、版本和风险标签。
- `McpHealthMonitor.status(serverId)`：返回连接状态、最近错误和重连时间。
- MCP 原始错误转换为统一 `AppError`，同时保留可审计的服务器错误码。

## 安全与兼容规则

- 首次连接必须显示服务器来源、启动命令/地址、请求权限和可见能力，用户明确确认后启用。
- 凭据通过安全存储或受控环境注入，不放入服务器配置 JSON、日志或模型上下文。
- 外部服务器返回的工具描述、资源内容和提示词均视为不可信输入。
- 服务器崩溃、协议异常或版本不匹配只影响该服务器，不应阻塞本地工具和聊天。
- 工具调用沿用 Phase 5 的确认、超时、审计、输出截断和取消规则。

## 阶段交付物

- MCP Client 和服务器配置管理。
- 工具发现与 Phase 5 工具框架的适配器。
- 连接健康、重连、权限和审计 UI。
- 至少一个 mock server 和一个真实目标服务器的验证记录。

## 验收标准

- 用户可添加、启用、禁用和删除 MCP server，状态和错误可诊断。
- 发现的工具能够显示 schema、来源和权限要求，并在确认后调用。
- 协议错误、服务器断开、超时和取消均有隔离与恢复行为。
- MCP 工具无法绕过本地权限策略、敏感数据规则或审计记录。
- 不启用外部服务器时，Phase 0-5 的核心功能不受影响。

## 测试与验证

- 协议测试：握手、版本协商、能力发现、请求关联、错误和断线。
- 安全测试：恶意 schema、提示词注入、超大响应、凭据泄漏和权限绕过。
- 稳定性测试：重复重连、服务器崩溃、并发调用和应用退出。
- 兼容性测试：mock server、目标 MCP server、不同 Windows 路径和编码。

## 风险与后续入口

- MCP server 的质量和权限范围差异较大，必须保留服务器级信任和禁用能力。
- 外部结果会参与 LLM 上下文，Phase 7 的主动行为也必须将其视为不可信信号。
- 后续增加资源订阅或提示模板时，先扩展适配器和审计模型再开放 UI。
