# Phase 3：记忆系统计划

## 目标

保存短期对话和经过筛选的长期信息，让桌宠能够在后续会话中稳定使用用户偏好、重要事件和使用习惯。

## 范围与边界

- 使用 SQLite 保存结构化数据和聊天记录。
- 抽象向量存储接口，可接入 FAISS、Chroma 或其他实现。
- 支持记忆提取、确认、检索、更新、删除和导出。
- 记忆默认最小化保存；不在本阶段实现复杂用户画像或跨设备同步。

## 前置条件与依赖

- Phase 2 已提供标准化会话、消息和 Persona 接口。
- 明确本地数据库位置、迁移工具、备份策略和加密要求。
- 确定嵌入模型来源、维度、版本与离线失败策略。

## 实施任务

1. 设计 SQLite schema：会话、消息、记忆条目、标签、来源、状态、时间戳和删除标记。
2. 建立迁移机制，迁移版本与应用版本独立记录，并支持失败回滚或安全停止启动。
3. 实现短期上下文服务，按时间、会话和 token 预算返回消息。
4. 实现长期记忆抽取器：从对话候选中提取用户偏好、事件和习惯，附带置信度与来源消息。
5. 实现记忆审核策略：高风险或低置信度内容需要用户确认，支持拒绝和永久删除。
6. 实现向量索引适配器、增删改和相似度检索，记录嵌入模型版本。
7. 实现 `ContextAssembler`，按相关性、时间、新鲜度和隐私等级组装 LLM 上下文。
8. 在设置页提供记忆列表、搜索、删除、全部清除和导出功能。

## 建议数据接口

- `MemoryRecord { id, kind, content, sourceMessageId, confidence, privacy, createdAt, updatedAt }`。
- `MemoryStore.create/update/delete/list(query)`：所有写入经过 schema 校验。
- `MemorySearch.search(query, filters, limit)`：返回记录、分数、来源和模型版本。
- `ContextAssembler.build(conversation, query, budget)`：返回带来源标记的只读上下文片段。

## 数据与隐私规则

- 原始聊天与长期记忆分开管理，记忆条目必须能追溯来源并单独删除。
- 密码、令牌、金融信息、健康信息等高敏感内容默认不提取为长期记忆。
- 用户删除操作必须同时清理结构化记录、向量索引和缓存。
- 导出文件不包含密钥，且由用户明确触发；导入前进行 schema 和大小校验。

## 阶段交付物

- SQLite 数据库、迁移脚本和 repository 层。
- 短期记忆与长期记忆服务及向量存储适配器。
- 记忆管理 UI 和导出/删除能力。
- 可被 Phase 2 调用的上下文组装接口。

## 验收标准

- 应用重启后最近对话可以恢复，长期记忆可被相关查询检索。
- 记忆条目包含来源、时间、置信度和隐私等级。
- 用户删除记忆后，后续检索和上下文中不再出现该条目。
- 数据库迁移可重复执行且不会丢失已有数据；迁移失败时应用给出明确错误。
- 无向量服务或嵌入失败时，短期聊天仍可工作并使用结构化回退。

## 测试与验证

- migration 测试：空库、旧版本、重复执行、失败回滚。
- repository 测试：CRUD、分页、软删除/硬删除和并发访问。
- 检索测试：相关性过滤、阈值、版本变更和无结果回退。
- 隐私测试：敏感信息不提取、删除级联、导出脱敏。
- 集成测试：对话到提取、检索、上下文注入的完整流程。

## 风险与后续入口

- 向量模型切换会造成索引不兼容，必须支持重建和版本共存策略。
- 自动提取可能产生错误记忆，确认和可追溯性是上线门槛。
- Phase 4 的语音转写默认进入短期上下文，是否进入长期记忆必须沿用同一审核流程。
