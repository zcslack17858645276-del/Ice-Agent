# Phase 0：桌宠基础框架计划

## 目标

建立可启动、可开发、可扩展的 Windows 桌面应用骨架，为后续角色、聊天和 Agent 能力提供稳定宿主。

## 范围与边界

- 使用 Tauri 2 作为桌面壳，前端采用 TypeScript 与 React 或 Vue（在初始化时确定一种并记录决策）。
- 实现透明、无边框、置顶窗口，以及基础拖动和窗口生命周期管理。
- 提供桌宠显示区、聊天区和设置入口的最小 UI 骨架。
- 暂不接入真实 LLM、数据库、语音或工具调用。

## 前置条件与依赖

- Windows 开发环境、Node.js LTS、包管理器、Rust stable、Tauri CLI。
- 确认应用标识、默认窗口尺寸、最小窗口尺寸和开发/生产构建命令。
- 前端与 Rust 之间只通过明确命名的 Tauri command 或事件通信。

## 实施任务

1. 初始化目录结构：`frontend/`、`backend/`、`database/`、`src-tauri/`、`docs/`，并补充基础 README。
2. 创建 Tauri 2 应用，配置开发服务器、生产构建、应用名称和 Windows 打包参数。
3. 配置透明窗口、无边框、置顶、隐藏任务栏图标（若平台能力允许）和合理的窗口安全策略。
4. 实现窗口拖动、显示/隐藏、退出和最小化等基础命令，并统一错误返回格式。
5. 实现应用布局：桌宠占位区域、可展开聊天面板、设置占位页和加载/错误状态。
6. 建立 TypeScript lint、format、类型检查和 Rust fmt/clippy 命令。
7. 增加最小 CI 检查，确保前端构建和 Rust 检查可重复执行。

## 建议接口

- `window:show`、`window:hide`、`window:toggle`、`window:close`：窗口控制事件。
- `window:drag`：由前端触发的拖动命令，参数只包含受校验的窗口上下文。
- `app:get_info`：返回版本、运行环境和功能开关，不返回敏感路径或密钥。
- 前端组件通过 `WindowService` 访问 Tauri API，不在业务组件中散落平台调用。

## 阶段交付物

- 可在 Windows 启动的透明无边框桌宠窗口。
- 可拖动、显示/隐藏、退出的基础窗口交互。
- 可进入聊天和设置占位页面的 UI 骨架。
- 一份技术决策记录，注明前端框架、窗口默认参数和 Tauri 配置。
- 可运行的开发、构建、检查命令。

## 验收标准

- 应用启动后窗口透明、无边框并置顶，桌宠占位内容可见。
- 拖动窗口不会改变布局，不出现明显闪烁或失焦异常。
- 聊天面板和设置入口可打开、关闭，空状态与错误状态有明确反馈。
- 退出路径会释放前端监听器和 Rust 资源，不留下后台进程。
- 全新环境按 README 执行安装、开发和构建命令可以成功完成。

## 测试与验证

- Rust：`cargo fmt --check`、`cargo clippy -- -D warnings`、单元测试覆盖窗口命令参数校验。
- 前端：类型检查、lint、组件渲染测试，覆盖面板开关和窗口服务失败提示。
- 手工 Windows 测试：透明度、置顶、拖动、退出、多显示器和 DPI 缩放。
- 构建测试：开发模式和生产模式各执行一次，确认资源路径正确。

## 风险与后续入口

- 透明窗口在不同 Windows 显卡驱动上的合成差异需要在真实设备验证。
- 窗口权限和平台 API 必须集中封装，避免后续功能直接依赖 Tauri 内部实现。
- Phase 1 只能在桌宠容器稳定后接入资源和状态机。
