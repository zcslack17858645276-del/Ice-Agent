# Phase 1：角色系统计划

## 目标

让桌宠具备可替换的视觉资源、基础动画、表情和可观察的生命状态。

## 范围与边界

- 首期支持 PNG/WebP 序列或静态资源，抽象资源接口以便未来接入 Live2D 或 3D。（png：assets/xglk.png，live2d：assets/live2d）
- 定义 `IDLE`、`THINKING`、`HAPPY`、`SAD`、`WORKING`、`SLEEPING` 状态。
- 实现状态切换、动画播放、表情切换和资源加载失败回退。
- 不在本阶段实现模型推理、情绪分析或嘴型同步。

## 前置条件与依赖

- Phase 0 的桌宠显示区域和生命周期事件可用。
- 确定资源目录、资源命名规则、版权/许可记录和默认角色。
- 定义 UI 状态与 AI/语音状态之间的事件契约。

## 实施任务

1. 建立 `AvatarAsset`、`AnimationClip`、`AvatarExpression` 和 `PetState` 类型。
2. 实现资源注册表，支持按角色、状态、表情和分辨率查找资源。
3. 实现状态机：状态进入、停留、退出、优先级、重复切换抑制和未知状态回退。
4. 实现动画控制器，支持播放、暂停、循环、一次性动画和资源预加载。
5. 将状态机与桌宠组件绑定，提供加载中、缺失资源和降级静态图状态。
6. 在设置页增加角色选择和动画开关；配置变更持久化接口先保留本地实现。
7. 为未来 Live2D/3D 实现定义 `AvatarRenderer` 适配边界，不提前耦合具体 SDK。

## 建议接口

- `AvatarRenderer.render(state, expression, asset)`：渲染器只负责显示。
- `AvatarStateMachine.transition(event)`：返回当前状态、目标状态和转换原因。
- `avatar:set_state`、`avatar:set_expression`、`avatar:preload`：统一事件名和参数校验。
- 资源清单使用版本化 JSON，禁止组件根据文件名猜测业务状态。

## 状态规则

- `THINKING`、`WORKING` 等临时状态结束后回到最近的稳定状态。
- `SLEEPING` 只能由明确的空闲/时间策略触发，不由单次渲染错误触发。
- 高优先级反馈动画可以打断循环动画，但必须恢复原状态。
- 资源加载失败时使用默认静态资源，并记录可诊断错误。

## 阶段交付物

- 至少一个可运行角色及每个基础状态的可见反馈。
- 可替换的资源清单和资源目录约定。
- 可测试的状态机和渲染器适配接口。
- 设置页中的角色选择、动画开关和错误提示。

## 验收标准

- 状态转换能驱动对应动画或静态表现，且不会因重复事件产生动画堆积。
- 缺失或损坏资源不会导致应用崩溃，桌宠仍可显示回退资源。
- 切换角色后状态机、预加载和当前表情保持一致。
- 所有状态均有可观察的进入和退出行为，调试日志包含状态、原因和时间。

## 测试与验证

- 状态机单元测试：合法转换、非法转换、优先级、打断恢复、未知状态。
- 组件测试：资源加载、回退显示、动画开关和角色切换。
- 手工测试：窗口透明背景、动画帧率、DPI 缩放和长时间循环播放。
- 资源检查：清单引用存在、格式可解码、许可证信息完整。

## 风险与后续入口

- 动画资源体积和预加载会影响启动时间，需记录资源大小与加载耗时。
- 状态事件命名必须稳定，Phase 2、4、5 将复用这些事件。
- Live2D/3D 接入应新增渲染器实现，不修改状态机公共契约。
