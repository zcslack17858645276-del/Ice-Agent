# Phase 4：语音交互系统计划

## 目标

完成语音输入到语音输出的闭环，并让桌宠在识别、思考、播放和打断期间提供一致的视觉反馈。

## 范围与边界

- 支持麦克风采集、ASR、LLM、TTS 和音频播放的可替换 provider。
- 首期支持 Whisper 类 ASR，以及 GPT-SoVITS 或 CosyVoice 类 TTS 适配。
- 支持按住说话或明确开始/停止录音；实时流式识别作为可选能力。
- 嘴型同步先支持音量/音素近似驱动，不承诺专业级唇形捕捉。

## 前置条件与依赖

- Phase 1 状态/动画接口、Phase 2 LLM 流程和 Phase 3 上下文策略可用。
- 明确麦克风权限、采样率、音频格式、缓存位置和录音保留策略。
- 为 ASR/TTS 准备 mock provider，确保无本地模型或网络时仍可测试。

## 实施任务

1. 定义 `AudioInputProvider`、`ASRProvider`、`TTSProvider`、`AudioPlayer` 接口。
2. 实现录音会话状态机：准备、录音、识别、等待回复、合成、播放、停止和错误。
3. 实现音频设备选择、权限提示、采样格式转换和输入电平监控。
4. 接入 ASR provider，支持最终文本、临时文本、置信度和取消。
5. 将 ASR 文本送入 Phase 2 会话服务，支持用户打断当前回复。
6. 接入 TTS provider，按句或流式片段合成并排队播放。
7. 将播放状态映射到角色动画，先实现播放音量驱动的嘴型/说话表现。
8. 在设置页提供输入输出设备、语音 provider、音量、自动播放和隐私开关。

## 建议接口

- `ASRProvider.transcribe(audio, signal)`：返回文本、语言、置信度和时间段。
- `TTSProvider.synthesize(text, options, signal)`：返回可播放音频流及可选时间标记。
- `VoiceSession.start/stop/cancel()`：会话状态变化通过事件总线发布。
- `AudioPlayer.play(stream, onLevel)`：只输出播放级别和生命周期事件，不暴露设备细节给 UI。

## 交互与隐私规则

- 未获得权限前不得启动麦克风；录音指示器必须持续可见。
- 停止录音、关闭应用或切换会话时立即取消未完成 ASR/TTS，并清理临时音频。
- 默认不永久保存原始录音；若用户开启保存，必须明确保存位置和删除入口。
- 语音识别文本作为用户输入，仍受 Persona、记忆和工具权限规则约束。

## 阶段交付物

- 可用的语音输入、识别、对话、合成和播放闭环。
- ASR/TTS provider 适配接口和至少一个可配置实现。
- 录音/播放状态与角色动画联动。
- 音频设备、权限、隐私和打断设置。

## 验收标准

- 用户可以完成一次语音提问并听到回复，期间角色状态连续且可理解。
- 无麦克风权限、设备断开、识别失败、合成失败和播放失败均有恢复路径。
- 用户停止或再次说话时，旧的识别/播放任务被取消，不出现串音。
- 默认设置不会把录音写入长期存储；关闭语音后不访问麦克风。

## 测试与验证

- provider 合约测试：空音频、噪声、超时、取消、分片顺序和错误映射。
- VoiceSession 状态测试：正常闭环、打断、重复启动、设备丢失和应用退出。
- 集成测试：mock ASR/LLM/TTS 驱动状态机和动画事件。
- 手工测试：不同采样率、耳机/扬声器回声、中文普通话、长文本和低网络质量。

## 风险与后续入口

- 本地模型的 CPU/GPU 占用可能影响桌宠渲染，需要监控耗时和资源使用。
- TTS 流式分句会影响延迟和语义连贯性，应由 provider 负责边界策略。
- Phase 5 工具执行产生的语音反馈必须复用播放队列和打断机制。
